# iPadOS visual grammar

Use current Apple HIG as authority; iPadOS visuals and windowing evolve.

- Preserve the product's Apple-platform identity while recomposing for larger or resizable windows rather than scaling iPhone measurements.
- Use hierarchy, columns, sidebars, inspectors/supporting regions, toolbars, and content width to make simultaneous context legible when UX calls for it.
- Do not increase font, corner radius, imagery, and whitespace proportionally just because the canvas is larger.
- Design for both touch and the visual states required by pointer, keyboard focus, Pencil, selection, drag/drop, and multiwindow contexts where relevant.
- Keep chrome recognizable as iPadOS while allowing product identity through content composition, type, color, imagery, data presentation, and purposeful motion.
- Test narrow and wide windows, portrait/landscape, large text, dark appearance, increased contrast, and reduced motion.
