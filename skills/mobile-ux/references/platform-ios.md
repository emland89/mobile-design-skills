# iOS / iPadOS behavioral conventions

Use Apple's current HIG as authority when current platform behavior matters.

## Principles
- Build on familiarity: system navigation, controls, gestures, feedback, and terminology where they fit.
- Give people agency and make recovery from mistakes easy.
- Keep important content/tasks prominent; do not let chrome dominate.
- Prefer standard gestures over custom gestures people must learn.
- Respect system back/navigation expectations and sheet dismissal semantics.
- Use tab bars for stable top-level destinations when appropriate; toolbars are for actions/navigation related to the current content.
- On iPad and resizable windows, adapt structure and navigation instead of stretching iPhone layouts.
- Support Dynamic Type, VoiceOver semantics, Reduce Motion, appearance changes, keyboard/pointer where relevant.
- Ask for permissions in context and explain value before system prompts when the reason is not self-evident.

## UX warning
Do not confuse "looks like Settings" with "feels native." Native behavior can support highly distinctive visual design.
