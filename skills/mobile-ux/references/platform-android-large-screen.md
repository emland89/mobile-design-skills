# Android tablets, foldables, and large-window behavior

Use current Android adaptive-app guidance as authority.

- Design against available window size and posture, not a fixed tablet model.
- Do not stretch compact layouts to fill large windows.
- Consider canonical structures such as list-detail and supporting pane when simultaneous context improves the task.
- Allow primary navigation to transform with space; for example, compact bottom navigation may become a navigation rail or other large-screen pattern when appropriate.
- Support runtime resizing, split-screen, desktop windowing, orientation changes, and foldable postures without losing task state.
- Use extra space for useful context, comparison, creation, or control—not decorative emptiness or gratuitous chrome.
- Consider keyboard, mouse/trackpad, stylus, drag/drop, and hover/focus where the device/context supports them while retaining touch usability.
- Do not assume a large Android screen means desktop interaction. Preserve Android conventions and adaptive behavior.
